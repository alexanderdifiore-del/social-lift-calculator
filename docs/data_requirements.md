# Data requirements and matching

Lollie reads CSV and Excel files. Files stay in the running app session on your computer; nothing is sent anywhere.
Column names do not have to match exactly: Lollie suggests a match for each field and shows it under *Import settings* so
you can correct it.

## Paid media report (WAVO or other advertising export)

| Field | Needed for | Required? |
| --- | --- | --- |
| Spend | All paid media figures | **Required** (the import stops without it) |
| Campaign name or campaign ID | Choosing a campaign | Strongly recommended (otherwise rows are grouped as "Unnamed campaign") |
| Reporting date (one row per day) | Spend over time, timing, date range | Needed for the chart and timing; totals work without it |
| Country / market | Country comparison, matching to streaming countries | Needed for Section D |
| Platform | Advertising platform filter | Recommended |
| Campaign start and end dates | Before / during / after windows | Recommended. If missing, the first and last reporting days are used and the summary says so. You can also type dates in Campaign Overview |
| Artist | Artist filter | Recommended |
| Promoted song / playlist, ISRC | Suggesting which song a campaign promoted | Optional |
| Impressions, video views, engagements, clicks, landing page views | Section B | Optional (shown as n/a when absent) |
| Objective, result type, results, results goal, budget | Cost per result, goal attainment, budget | Optional |
| Currency | Money formatting | Optional (taken from a header such as `Spend (USD)`, otherwise the sidebar default) |

Rules Lollie follows:

* **Result definitions are never combined.** Video views, landing page views, clicks and engagements are reported as separate
* **Budget is counted once** per campaign and country, not once per daily row.
* **Different currencies are never added together.** If a file has several, you choose one to display.
* Total or summary rows (for example "Total") are ignored so they are not counted twice.
* The same file uploaded twice is skipped. If WAVO and a platform export both report the same campaign-day, the platform
  export is used.
* Landing page views are used as the result for landing-page-view campaigns only when the report provides them.

## Streaming report (Opus or another approved export)

| Field | Needed for | Required? |
| --- | --- | --- |
| Date (daily) | Everything | **Required** |
| Streams | Everything | **Required** |
| Track title and/or ISRC | Choosing a song, playlists, catalog | Strongly recommended. If missing, type one track name for the whole file |
| Country | Country comparison | Needed for Section D |
| DSP (streaming service) | DSP filter | Optional |
| Artist | Artist filter | Optional |
| Playlist / source | Separating playlist-attributed streams | Optional |

Rules Lollie follows:

* **Total track streams and playlist / source-attributed streams are different things.** Rows with a playlist or source name
  are kept in a separate table and are never added to total streams. If a whole file contains only playlist-attributed
  streams, mark it as such in *Import settings*.
* **Daily analysis only.** If the file is hourly, hours are added up into days, but only for days with all 24 hours. Partial
  days are left out so they do not look like a drop. Lollie never creates hourly figures.
* **Missing days stay missing.** They are not filled with zero or estimated.
* **Roll-up rows are not double counted.** If a file contains "All countries" rows next to country rows (or "All DSPs" next to
  individual services) for the same track and day, the roll-up rows are removed and Lollie says so.
* Identical repeated rows are removed. If two files give different numbers for the same track, country, service and day, the
  later file is kept and a warning is shown.

## Track and playlist campaigns

A campaign can promote **a single song**, **a playlist or several songs**, or **the artist's catalog**.

* Playlist and multi-track campaigns need a list of tracks: choose them in Campaign Overview, or upload a track list
  (title, ISRC, optional artist, optional added / removed dates). Track membership has to come from you. Tick the
  confirmation box when you have verified it; the summary notes when you have not.
* A Spotify playlist link can be pasted as a **reference only**. Lollie does not call Spotify or read playlists, and it
  cannot see a playlist's private streaming or past membership.
* Tracks are matched to streaming rows by ISRC first, then by title and artist. Tracks that cannot be found are listed.
* Streams are added up across tracks once per track and day. Song-by-song results stay visible so one track is not hidden inside
  a playlist total. Lollie does not claim that a playlist's total streams were generated by the playlist.
* Catalog analysis needs you to confirm the streaming file covers the whole catalog.

## How paid media and streaming are matched

* **Countries** are matched by ISO country code. `US`, `USA`, `United States` and `U.S.` all become the same market, and
  `UK` / `United Kingdom` / `GB` do too. Labels that are not recognised are kept as typed and flagged; they are never guessed
  and cannot be matched.
* **Dates** are matched by calendar day. Mixed formats are parsed per value. A date such as `03/04/2026` is read
  month-first; if your files use day-first dates, export the dates as `YYYY-MM-DD`.
* **Campaign to song** is chosen by you. If the advertising report names a song or ISRC, Lollie suggests it.
* **Campaign dates** come from the report's start and end columns when present, otherwise from the first and last
  reporting day, otherwise from dates you type.
